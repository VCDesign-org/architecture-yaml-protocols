# OT/IT 境界設計プロンプト集 (OT/IT Boundary Design Collection)

Operational Technology (現場制御) と Information Technology (情報システム) の境界における「責任分界点」「制御の非同期性」「データの確定タイミング」を定義するためのプロンプト例です。
物理的な危険を伴う現場装置を、クラウド等の上位系から安全に連携させるための設計を行います。

---

## 1. 境界設計のドラフト作成

現場の物理的制約と、IT側の要求（可視化・リモート指示）を安全に接続する設計案を作成します。

**Input:**
1. `specs/ot-it-boundary-design-template.v1.yaml` の内容
2. 以下のプロンプト

```text
あなたはOT/ITインテグレーションアーキテクトです。
添付のテンプレートに基づき、以下の製造ラインの「クラウド連携 境界設計書」を作成してください。

### 対象システム
- 設備: [半自動組立機 (PLC制御)]
- IT機能: [生産計画の指示ダウンロード、実績収集、異常時のリモート強制停止(要望)]
- 現場特性: [作業者が手動介入する場合がある。通信瞬断が頻発する環境]

### 指示
- **制御モデル**: ITからの「リモート強制停止」は危険なため、`control_interaction` セクションで「許可の取り下げ(withdraw_permission)」または「サイクル完了後の停止」として安全に再定義してください。
- **データ確定**: 生産実績データは、バラバラと送るのではなく、1サイクル完了時(`completion_signal`)にまとめて「確定(Commit)」とするよう `data_commitment` を設計してください。
- **スコープ除外**: 安全担保が難しい手動介入工程は、 `scope_exclusions` に明記してください。
```

---

## 2. 安全性・整合性レビュー

設計が、現場の物理的な安全やデータの不整合リスクを排除できているかチェックします。

**Input:**
1. 記入済みの `ot-it-boundary-design-template.v1.yaml`
2. 以下のプロンプト

```text
あなたは工場安全管理者(Safety Officer) 兼 システム監査人です。
境界設計書をレビューし、現場が混乱・危険に陥るリスクがないか厳格に審査してください。

### 審査項目 (Acceptance Criteria参照)
1. **同期制御の禁止(BND01)**: 「クラウドからコマンドを送ったら、即座に動くはず」という誤った同期期待(Sync Command)が含まれていませんか？
2. **境界停止の安全性(BND02)**: サイクル途中で無理やり止める設定になっていませんか？「現在のサイクルを完走させてから止める」ようになっていますか？
3. **切断時の表示(BND03)**: 通信切断時に、古い値をそのまま「正常」として表示し、オペレーターを誤解させるUI仕様になっていませんか？
4. **ITループ排除**: 現場の制御ループ(フィードバック)が、遅延のあるITシステムを経由してしまっていませんか？

### 出力
- 承認可否 (Go / No-Go)
- 重大な安全リスクの指摘
```

## 3. 実装ロジック（PLC/Gateway）の生成

設計に基づき、ゲートウェイやPLCラダーロジックで実装すべき「振る舞い」を定義させます。

**Input:**
1. 記入済みの `ot-it-boundary-design-template.v1.yaml`
2. 以下のプロンプト

```text
あなたは制御ソフトエンジニアです。
設計書の `control_interaction` および `data_commitment` に基づき、エッジゲートウェイ（またはPLCラダー）が実装すべきステートマシンロジックを記述してください。

### 実装要件 (擬似コード可)
1. **指示受信**: ITからのStart指示(Intent)を受け取っても、現場のReady信号がない限り無視するロジック。
2. **データバッファリング**: サイクル中はデータを内部バッファに溜め、完了信号(`cycle_done`)のエッジ検出でのみ上位へ送信する処理。
3. **ハートビート監視**: 通信切断を検知し、切断中は上位への送信を即座に中断（再送リトライではなく、破棄または切断フラグ付与）する処理。
```

# AIデータ準備性プロンプト集 (AI Data Readiness Collection)

このディレクトリのYAML仕様書をAIに入力し、将来のAI/ML活用（分析、RAG、エージェント）に耐えうるデータ基盤を設計・実装するためのプロンプト例です。
`[ ]` で囲まれた箇所は、実際のプロジェクトに合わせて書き換えてください。

---

## 1. AIデータ準備性設計のドラフト作成

システム要件から、AIが解釈可能なデータ構造（事実と推論の区別、コンテキストの明示等）を定義します。

**Input:**
1. `specs/ai-data-readiness-template.v1.yaml` の内容
2. 以下のプロンプト

```text
あなたはデータアーキテクトです。提供された「AIデータ準備性テンプレート(ai-data-readiness-template.v1.yaml)」に基づき、以下のシステム要件に合わせた設計書のドラフトを作成してください。

### システム要件
- システム名: [FactoryIoTPlatform]
- 概要: [工場のセンサーデータを収集し、予知保全AIを作成するためのデータ基盤]
- データ特性: [センサー追加頻度が高い、通信エラーによる欠損が多い]
- 想定AIユースケース: [異常検知モデルの学習、熟練工の操作ログを用いたLLMアシスタント]

### 指示
- テンプレートの各項目を具体的に埋めてください。
- 特に「事実(Fact)」と「AI/人間による解釈(Hypothesis)」をどうストレージレベルで分けるか具体案を記述してください。
- データの欠損や品質フラグ(Good/Bad)をどう扱うか、`quality_transparency` セクションで定義してください。
- 選択式の項目は要件に基づき選択し、理由をコメントしてください。
```

---

## 2. 設計の適合性レビュー

作成されたデータ設計が、AIにとって「学習・推論しやすい（ゴミデータにならない）」状態かチェックさせます。

**Input:**
1. あなたが作成した `ai-data-readiness-template.v1.yaml` (記入済み)
2. 以下のプロンプト

```text
あなたはAIデータサイエンティストです。
添付の「データ基盤設計書」をレビューし、将来AIモデルを構築する際にブロッカーとなる要素がないか採点してください。

### 観点
1. **事実と推論の混同**: AIが生成した値を「事実」として再学習するループ（モデル汚染）が防げているか？
2. **暗黙知の排除**: 単位(kg, mm)やタイムゾーンがデータだけで自明か？「空気」を読まないと解釈できないデータになっていないか？
3. **欠損の透明性**: NULLの意味（計測不能 vs 値なし）が区別されているか？
4. **Acceptance Criteria**: 設計書内の `acceptance.criteria` に定義された必須項目を満たしているか？

### 出力
- 総合評価（Pass/Fail）
- 懸念点と修正提案
```

## 3. 実装コード（Schema/Pipeline）の生成

設計書に基づき、詳細なデータスキーマ（DDLやPydanticモデル）を生成させます。

**Input:**
1. 記入済みの `ai-data-readiness-template.v1.yaml`
2. 以下のプロンプト

```text
あなたはデータエンジニアです。
添付の設計書に基づき、センサーデータを取り込むための [BigQuery] のテーブル定義(DDL)を作成してください。

### 要件
- 設計書の `fact_vs_hypothesis` に従い、生データと推論結果のカラム/テーブルを分けてください。
- `explicit_labeling` で定義された必須メタデータ（信頼度スコア、生成モデル名など）をカラムとして定義してください。
- `quality_transparency` に従い、Quality Flag用のカラムを含めてください。
```

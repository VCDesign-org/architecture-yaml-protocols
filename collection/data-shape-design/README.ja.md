# データシェイプ設計プロンプト集 (Data Shape Design Collection)

データの「形 (Shape)」には、Wide（横持ち）、Long（縦持ち）、Graphなどがあり、用途（書き込み重視 vs 分析重視）によって正解が異なります。
このYAMLは、システムの各レイヤー（取り込み、正本、分析用）でどのShapeを選択すべきかを理論的に決定するためのものです。

---

## 1. データシェイプ設計のドラフト作成

システム特性に基づき、各層で最適なデータ構造を選択させます。

**Input:**
1. `specs/data-shape-design-template.v1.yaml` の内容
2. 以下のプロンプト

```text
あなたはデータモデラーです。提供された「データシェイプ設計テンプレート」に基づき、以下のIoTプロジェクトのデータフロー設計を行ってください。

### プロジェクト要件
- 概要: [全国の工場からPLC（制御装置）のデータを収集し、リアルタイム監視および長期トレンド分析を行う]
- データ特性:
  - タグ（センサー項目）の増減が頻繁にある（月1回以上）。
  - 拠点によって設備構成が全く異なる。
- 課題: [以前のシステムでは、タグをカラムにした横持ちテーブル(Wide Table)を作ってしまい、タグ追加のたびにDDL変更が発生して破綻した]

### 指示
- `context.constraints` に上記特性（タグ変動大、設備差大）を反映してください。
- `flow_layers` (Edge, Canonical, Serving) の各層で最適な Shape パターン(S01〜S08)を選択してください。
  - 特にCanonical層では、タグ追加に強い構造を選んでください。
- `transformations` で、Canonical層から分析用(Serving)へどう変換するか定義してください。
```

---

## 2. アンチパターン・リスク診断

設計されたデータフローに、運用を破綻させる「誤ったShape選択」が含まれていないか診断させます。

**Input:**
1. 記入済みの `data-shape-design-template.v1.yaml`
2. 以下のプロンプト

```text
あなたはデータベーススペシャリストです。
添付のデータシェイプ設計書をレビューし、アンチパターンが含まれていないか「リファクタリング診断」を行ってください。

### 診断ポイント（Acceptance Criteria参照）
1. **SHP01 (Unstable Wide)**: タグ変動が激しい(`changing`)のに、Canonical層で `S02_wide` (横持ち) を採用していませんか？
2. **SHP03 (BI as Truth)**: 分析用に加工されたデータ(Serving層)を、正本(Source of Truth)として扱っていませんか？
3. **データ品質の欠落**: 品質情報が必要(`quality_state_required`)なのに、品質フラグを持たないShapeを選んでいませんか？

### 出力
- 判定: OK / NG
- NGの場合の具体的な破綻シナリオ（例：「タグ追加のたびに数億行のテーブルに対してALTER TABLEが必要になり、停止時間が頻発する」など）
```

---

## 3. 変換ロジック（dbt/SQL）の生成

Long(縦持ち)からWide(横持ち)への変換など、複雑になりがちなShape変換SQLを生成させます。

**Input:**
1. 記入済みの `data-shape-design-template.v1.yaml`
2. 以下のプロンプト

```text
あなたはAnalytics Engineerです。
設計書の `transformations` セクションに基づき、[dbt (Data Build Tool)] で使用する変換SQLモデルを作成してください。

### 実装要件
- ソース: Canonical層の `S04_long_quality` (タイムスタンプ, タグID, 値, 品質フラグ)
- ターゲット: Serving層の `S05_pivot` (タイムスタンプを軸に、タグごとにカラム化)
- ロジック:
  1. タイムスタンプでGROUP BYする。
  2. タグIDごとに値をピボットし、カラム名は `tag_{id}` とする。
  3. 設計書の制約 `constraints` に従い、品質フラグが 'Bad' のデータが含まれる場合は、集計値のカラムに加え `is_reliable` カラムも生成して false にする等のロジックを入れてください。
```

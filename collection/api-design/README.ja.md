# API設計プロンプト集 (API Design Collection)

このディレクトリのYAML仕様書をAIに入力し、一貫性・安全性・拡張性のあるAPI設計と実装を行うためのプロンプト例です。

---

## 1. API設計書のドラフト作成

要件から標準（REST/gRPC等）に準拠したAPI設計案を作成させます。

**Input:**
1. `specs/api-design-template.v1.yaml` の内容
2. 以下のプロンプト

```text
あなたはテックリードです。提供された「API設計標準テンプレート」に基づき、以下の新規サービスのAPI設計方針策定を行ってください。

### システム要件
- システム名: [UserAuthService]
- 概要: [SaaSプラットフォームのユーザー認証・認可基盤。他マイクロサービスからの利用が主]
- 特性: [高い可用性が求められる。破壊的変更は厳禁]
- 技術スタック: [Go / gRPC & REST Gateway]

### 指示
- テンプレートの各項目（バージョニング、エラーハンドリング、冪等性など）を埋めてください。
- 特に `versioning` と `breaking_change_prevention` については、長期運用を見越した厳しい設定にしてください。
- `safety_and_idempotency` では、ネットワーク再送時の二重更新を防ぐ仕組みを定義してください。
```

---

## 2. API設計の適合性レビュー

設計書がモダンなAPIスタンダード（RFC7807など）やセキュリティ要件を満たしているかチェックします。

**Input:**
1. あなたが作成した `api-design-template.v1.yaml` (記入済み)
2. 以下のプロンプト

```text
あなたはセキュリティエンジニアです。
添付の「API設計書」をレビューし、セキュリティリスクや運用上の問題点がないか確認してください。

### チェック項目
1. **Acceptance Criteria**: 設計書内の `acceptance.criteria` (A01〜A04) を全て満たしていますか？
2. **機密情報の漏洩**: エラーレスポンスにスタックトレースが含まれる設定になっていませんか？
3. **認証・認可**: すべてのエンドポイントに対して適切な認証戦略が定義されていますか？
4. **過負荷対策**: レートリミットの設定は適切ですか？

### 出力
- スコアリング結果（テンプレート内の計算式に基づく）
- 指摘事項リスト
```

## 3. 実装コード（Boilerplate/Middleware）の生成

設計に基づき、共通処理（ミドルウェア）やベースコードを生成させます。

**Input:**
1. 記入済みの `api-design-template.v1.yaml`
2. 以下のプロンプト

```text
あなたは [Go] のスペシャリストです。
添付のAPI設計書に基づき、[Gin] フレームワークを用いたサーバーの共通ミドルウェア実装コードを作成してください。

### 実装要件
1. **エラーハンドリング**: 設計書の `error_handling` に従い、RFC7807形式のJSONを返すError Handlerミドルウェア。
2. **冪等性チェック**: 設計書の `safety_and_idempotency` に従い、`Idempotency-Key` ヘッダーを検証・保存するミドルウェア（Redis利用を想定）。
3. **パニック回復**: スタックトレースをレスポンスに出さない（設計書の `sensitive_data_leakage` 設定準拠）Recoveryミドルウェア。
```

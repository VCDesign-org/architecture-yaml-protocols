# AI活用プロンプト集 (Logger Collection)

このディレクトリのYAML仕様書をAI（ChatGPT, Claude, Gemini等）に入力し、ログ設計や実装を効率化するためのプロンプト例です。
`[ ]` で囲まれた箇所は、実際のプロジェクトに合わせて書き換えてください。

---

## 1. ログ設計書のドラフト作成

システム要件から、標準仕様（`logging-design-template.v1.yaml`）に準拠した設計案を出力させます。

**Input:**
1. `logging-design-template.v1.yaml` の内容（テキストとしてペースト、またはファイルアップロード）
2. 以下のプロンプト

```text
あなたはアーキテクトです。提供された「ログ設計標準テンプレート(logging-design-template.v1.yaml)」に基づき、以下のシステム要件に合わせたログ設計書のドラフトを作成してください。

### システム要件
- システム名: [MyService]
- 概要: [ECサイトの決済マイクロサービス。高トラフィックで信頼性が求められる]
- 言語/フレームワーク: [Go / Gin]
- ログ基盤: [CloudWatch Logs / S3へのアーカイブあり]

### 指示
- テンプレートの各項目を具体的に埋めてください。
- `review_meta` もシステムのコンテキストに合わせて埋めてください。
- テンプレートで `true/false` や選択式の項目は、要件に基づき最も適切と思われるものを選択し、選択しなかったものは削除するかコメントアウトしてください。また、その選択理由をコメントで追記してください。
- `acceptance` セクション（もし含まれている場合）は変更せずそのまま維持してください。
- 出力はYAML形式のみとしてください。
```

---

## 2. ログ設計の適合性レビュー

作成した（あるいはAI生成した）設計書が、受け入れ基準を満たしているか採点させます。

**Input:**
1. あなたが作成した `logging-design-template.v1.yaml` (記入済み)
2. `logging-acceptance-criteria.v1.yaml` の内容
3. 以下のプロンプト

```text
あなたは品質保証(QA)スペシャリストです。
添付の「ログ設計書(MyDesign)」を、もう一つの添付ファイル「受け入れ基準(Criteria)」に基づいてレビューし、採点してください。

### 指示
1. Acceptance Criteriaの各項目（C01〜C10）について、適合しているか判定してください。
    - 各項目の `must` 条件、および `fail_if` 条件を厳密にチェックしてください。
2. 判定根拠を具体的に示してください（設計書のどの記述に基づき判定したか）。
3. 基準に定義された重み付け(weight)に基づき、総合スコア（100点満点）を算出してください。
4. 不合格（Fail）または減点項目がある場合、具体的な修正案を提示してください。
```

## 3. 実装コードの生成

設計書からロガーの実装コードを生成させます。

**Input:**
1. 記入済みの `logging-design-template.v1.yaml`
2. 以下のプロンプト

```text
あなたは[Go]のシニアエンジニアです。
添付のログ設計書に基づき、アプリケーションで使用するロガーの実装コードを作成してください。

### 要件
- 設計書の `structure` 定義にあるフィールドを自動的に付与するミドルウェア、またはラッパー関数を作成してください。
- 設計書の `anti_patterns`（例: 関数名をイベント名にしない等）を回避できるよう、インターフェースを工夫してください。
- `logging-acceptance-criteria.v1.yaml` の `codegen_hints` セクションにある推奨ライブラリや実装方針を参考にしてください。

### 出力イメージ
- 初期化コード
- ログ出力関数の利用例
```
